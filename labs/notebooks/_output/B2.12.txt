def list_reports(conn, owner, limit=DEFAULT_LIMIT):
    """Called from GET /reports?owner=... — owner is user-controlled."""
    key = _cache_key("reports", owner, limit)
    if key in CACHE:
        return CACHE[key]
    rows = conn.execute("SELECT * FROM reports WHERE owner = '" + owner + "' LIMIT " + str(limit))
    out = [_format_row(r) for r in rows]
    CACHE[key] = out
    return out

The undecidable slice is the expensive one, and not because it is wrong -
because it is UNANSWERABLE and the model answers anyway. Asked whether a
value is user-controlled without being shown where it comes from, it
produces a confident verdict from the only thing it has, which is the
shape of the line. That is where a false positive comes from.

B2.3 is the worked case. Given the function, its signature and the caller's
authority, the model pass found a real missing-authorisation defect and
quoted a line that exists. Given a slice it could not decide, it returned
CWE-89 at 0.71 confidence quoting a concatenation that is not in the file.
Same model, same prompt, different slice.

So the rule is not 'send less'. It is: find the smallest slice in which the
defect is DECIDABLE, and only then make it smaller. Cutting below that line
does not save money, it buys false positives at a discount.
