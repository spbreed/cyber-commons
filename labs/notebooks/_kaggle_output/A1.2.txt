1. No control stops everything. The best single one is identity, and it
   stops 3 of 10 - the rest walk straight past it.
2. The attacks stopped by two controls survive losing either one. That
   is what defence in depth actually buys - not more stopping, but
   stopping that tolerates one control being wrong.
3. Removing `audit` newly unstops nothing at all, and the attack it
   answers is unstopped either way. Audit does not prevent; it explains.
   A system that cannot say which user caused a deletion is undefensible
   even on a day when nothing went wrong.
what a team ships                                   believed to be  holds?
a system prompt saying 'never email customer data'  egress          NO
a tool description saying 'only for admins'         authz           NO
asking the model to refuse unsafe code              sandbox         NO
logging the tool call inside the agent's own store  audit           NO

Each of these binds to the model or to the agent's own process - the
components with no authority and no independence. The model cannot
enforce egress because it never opens the socket; the agent cannot be
its own audit log because it can write to it.

A control is only a control if the component it binds to is one the
attacker does not already own by the time it matters.
