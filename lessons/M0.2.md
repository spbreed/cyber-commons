## What the board looks like

Draw it in this order — the sequence *is* the argument:

1. A box labelled **context**, feeding a box labelled **model**.
2. An arrow out to **tools** (the action plane). Circle it: this is the only
   part that changes state.
3. An arrow from tools back to a diamond labelled **verify**.
4. A **budget** counter in the corner, ticking down on every pass.

Then erase the verify diamond and ask the room what stops the loop now. The
answer — *nothing but the budget* — is the whole lesson.

## Running it live

```bash
cd labs/m0-agent-loop
python3 loop.py --verifier pytest      # honest oracle
python3 loop.py --verifier llm-judge   # same-family judge
```

The second command declares success on `return a - b`. Let that sit for a
moment before explaining it.

## Gotchas

- **Stale bytecode makes the oracle lie.** The first version of this lab read a
  cached `.pyc` and reported on code that was no longer on disk. The lab now
  clears `__pycache__` before every verify — worth showing on the board, because
  a verifier reading stale state is a real production failure mode, not a toy one.
- With `--model stub` the judge is scripted to approve. That is deliberate: it
  makes the failure reproducible for teaching. Never quote a stub run as a result.
