01 / Need of the hour

Attack is already automated. Defence mostly is not.

The adversary side got its productivity upgrade first: discovery, exploitation and lateral movement now run as tooling, while the defending side still reviews the result at human speed, once a quarter, by hand. The name for the threshold where that gap closes on you is the cyber singularity — not a prophecy about machines waking up, but a practical point where an intrusion's decision-to-action loop runs faster than the people reviewing it. Parts of security are already past it, and the clock is public.

Closing it has two halves and they are one skill set: using AI to do the security work, and securing the AI you have already deployed. Most training covers one. A curriculum that covers only the first teaches you to trust a system nobody has tested; only the second, and you are defending at last year's speed.

Their loop

Minutes. Recon, foothold, escalation and exfiltration executed by tooling that never sleeps, never tires, and costs almost nothing to run again.

Your loop

A pentest once a year. A change window measured in days. An on-call engineer who reads the alert at minute twenty — and the attacker is already on the second host.

You cannot close that gap by hand. You close it by testing yourself at the same speed.

The answer to machine-speed offense is agentic offensive capability of your own — authorised, scoped, and pointed only at systems you operate. Not an annual engagement, but a loop that runs continuously against your own estate, so the reachable path is found by your agent before it is found by theirs. That capability is what Function C teaches, and it is deliberately built to run at any size: the same loop that covers a bank's estate runs on one laptop for a clinic, a school district or a two-person NGO.

  • Continuous, not annualA pentest is a photograph. Your attack surface changes every deploy, and so must the testing.
  • Every size, same loopOpen weights and open tooling mean the capability is not gated behind a six-figure retainer — and the same lesson runs on a frontier model when you have one.
  • Your estate onlyHard scope enforcement, destructive-action gating and a full audit trail are part of the harness, not an afterthought.

Every offensive lesson here runs inside a sealed lab against targets you own or that are published for the purpose. Scope control and containment are taught before exploitation is.

02 / One place

What does not scale by itself is what you have to learn.

Attacking needs one working path. Defending needs all of them closed. That asymmetry is why offensive capability diffuses on its own and defensive capability has to be deliberately spread — and it is why the work that matters now is the half no tool does on your behalf.

What scales at almost no cost
  • Autonomous discovery — agents that read code and find real vulnerabilities
  • Exploit generation at the speed of a build pipeline
  • Campaigns without headcount
  • One path is enough
What does not scale by itself
  • Judgement — which finding is real, and which confident answer is a hallucination
  • Trust in your own tools — a probabilistic scanner is worthless unmeasured
  • Control-plane design — identity, delegation, containment, stop authority
  • Every path must hold
If only the best-funded teams learn to direct, doubt and prove these systems, the gap between them and the hospital, the school district, the two-person NGO becomes the softest target in the network we all share.

Everyone in this field is now a beginner at something.

The tools changed underneath the job. A SOC analyst who cannot say why an agent reached a conclusion cannot supervise it. An AppSec engineer scoring a probabilistic scanner on finding count is measuring the number that improves when it finds less. A governance lead writing controls for a model has to name the component the control attaches to.

None of that is learnable from a vendor page. So these lessons are written two ways at once: for practitioners already carrying the pager, and for the people trying to get into the field who need a starting point that is not a certification syllabus.

So it is all in one place.

Best-in-class defensive practice is real, and it is scattered — across vendor blogs, conference talks, a paper nobody outside the lab reads, and closed Slacks you have to be invited to. Cyber Commons puts it in one place and organises it the way a security org actually is: 5 functions, 12 chapters, 120 lessons, taught in the order the work happens.

The architecture comes first and the tactics hang off it. Every risk and every control in the whole curriculum names a component from one reference architecture, so "secure the agent" always has a referent — and 117 of the lessons run one of 121 agent skills you can open and read, rather than describing what a tool would do.

03 / Who writes it

Curated by the world's top cyber practitioners.

Not a syllabus assembled from vendor documentation. The people writing these lessons are working on the latest of this across several regulated industries — where a control has to survive an audit as well as an attacker, and "the model said so" is not an answer you can give a supervisor. That is why every lesson names a risk, a control and a lab, in that order, and why the labs produce evidence rather than a screenshot.

It is also why the curriculum covers both directions in one place: securing AI systems, and using AI to do security work. Most material picks a side. The two share an architecture, a threat model and a set of failure modes, and splitting them is what leaves teams defending a system they never mapped.

How a lesson works

See it drawn, watch it run, then run it yourself.

Reading about a control doesn't build the instinct to ship it. Every lesson has the same three-part shape.

01 / SEE

Lightboard, not lecture

The concept is drawn out so the mental model lands before any code does. You leave understanding the why, not copying the how.

02 / WATCH

Live demo, real execution

An actual agent against an actual target. No slides of screenshots — the thing works on screen, and it works on your machine.

03 / RUN

One click, your own copy

Most lessons are reading lessons. The ones that run execute an agent skill from the repository, or call a model through one adapter — hit Run on Kaggle and it opens in your own account, no install, no GPU.

Every notebook is executed before it ships. All 120 run top to bottom in CI, the output is committed to the repository, and the same 120 are re-run on a clean Kaggle kernel and checked line for line against it — so a lesson that claims a result has actually produced it. Nothing here is pseudo-code.
