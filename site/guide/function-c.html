▦The idea the whole course hangs off

Read this before the first lesson. A taught session opens with it; alone, read it and move on.

One chapter, twenty lessons, one pipeline built end to end. C2.0 splits it the way the function is organised: what runs before a deploy, and what runs after. Everything else is one stage of that pipeline, in the order it runs.

The spine is: threat model from what the estate already knows → deterministic SAST, then a model pass → deduplicate and verify in context → filter to what is reachable → replicate in a sandbox → supply chain → dynamic exploitation → chaining → the agentic pentest in three colours (white, black, grey box) → severity and reporting → remediation proven before the merge request → context engineering to cut the false positives → attesting control intent.

The argument underneath all twenty is C2.1's: this is security engineering, so build a harness rather than a prompt. Every stage has a deterministic half and a model half, and the deterministic half is what makes the model half checkable. A pipeline whose only verifier is another model has no verifier.

C2 — The AI SDLC — an Agentic AppSec Pipeline, Before and After Deploy

One chapter and the whole function. Twenty lessons in pipeline order, from the threat model to the attestation, with the before-deploy and after-deploy split named in C2.0 and held for the rest.

Two of the twenty are marked Bonus — C2.14 on the controls an offensive agent runs inside, and C2.19 on the pipeline in production. Neither is optional reading if you intend to run an offensive agent against anything you do not own.

For a room

Twenty dependent stages is the longest single arc in the curriculum. Draw the pipeline once and add to it, rather than re-drawing per lesson.

C2.1What building a harness means in security engineering1 skill
Risk

A harness whose verifier is the model agreeing with itself does not fail loudly. It succeeds incorrectly, files a clean trace, and the bug is found by whoever merged the patch.

Control

An independent verifier, and a budget that stops the loop when it cannot pass.

Day 0 — why it matters
A harness whose verifier is the model agreeing with itself does not fail loudly. It succeeds quietly and wrongly.

Day 2 — measure. agreement between the verifier and held-out ground truth (rate); loops stopped by budget rather than by success (count)

The lab. Run the same loop twice — once with no verifier, once with one.

C2.13Grey-box agentic pentest — one credential per role, and the matrix it fills1 skill
Risk

Object-level authorisation is assumed correct because the endpoint list was covered, and BOLA lives in the cells nobody enumerated.

Control

A roles-by-objects-by-verbs matrix with every cell marked tested, assumed or unreachable, and the assumed cells ranked by blast radius.
